# Plan: Expand editor with more standard writing tools

## Current state
- The client editor is a TipTap-based rich-text editor, not a code editor. Core editing is built around `@tiptap/react` + `@tiptap/starter-kit` in `client/src/editor/Editor.tsx` and `client/src/editor/editorConfig.ts`.
- The toolbar is intentionally minimal today: bold, italic, heading, bullet list, ordered list, and blockquote in `client/src/editor/Toolbar.tsx`.
- There is already custom link support in `client/src/editor/extensions/link.ts` and a custom bubble menu portal in `client/src/editor/BubbleMenuPortal.tsx`.
- Collaboration is already integrated through Yjs, so new editing extensions need to remain compatible with collaborative document updates.

## Goal
Make the editor feel more like a standard modern writing editor by expanding rich-text tooling first, while preserving the current TipTap/Yjs architecture.

## Recommended approach

### Phase 1: Extend the schema with standard writing features
Add TipTap extensions that are widely expected in modern editors and are compatible with collaborative editing:
- Inline formatting: underline, strike, highlight, code.
- Block formatting: multiple heading levels, code block, horizontal rule.
- Layout/content tools: text alignment, task lists, tables.
- Utility UX: placeholder extension, character count / word count integration, improved link behavior.

Planned package additions in `client/package.json`:
- `@tiptap/extension-underline`
- `@tiptap/extension-highlight`
- `@tiptap/extension-text-align`
- `@tiptap/extension-task-list`
- `@tiptap/extension-task-item`
- `@tiptap/extension-table`
- `@tiptap/extension-table-row`
- `@tiptap/extension-table-header`
- `@tiptap/extension-table-cell`
- `@tiptap/extension-placeholder`
- `@tiptap/extension-character-count`
- optionally `@tiptap/extension-horizontal-rule`

Implementation target:
- Expand `createEditorExtensions` in `client/src/editor/editorConfig.ts` so all editor capabilities are centrally configured and collaboration toggling stays isolated.

### Phase 2: Upgrade the toolbar into a standard formatting surface
Refactor `client/src/editor/Toolbar.tsx` from a fixed small button row into grouped controls with clear formatting affordances:
- Inline group: bold, italic, underline, strike, highlight, inline code, link.
- Block group: paragraph, H1/H2/H3, quote, code block.
- List group: bullet list, ordered list, task list.
- Alignment group: left, center, right, justify.
- Insert group: horizontal rule, table insert.

UX details:
- Keep the current active-state styling pattern.
- Disable actions that are invalid for the current selection with `editor.can()` where useful.
- Prefer small helper functions/config arrays so toolbar growth stays maintainable.

### Phase 3: Improve contextual editing UX
Use the existing bubble menu and editor shell to make the editor behave more like a standard app:
- Expand the bubble menu with underline/highlight/link remove/code actions.
- Replace `window.prompt` link editing in `client/src/editor/Editor.tsx` with an inline popover/input anchored to the toolbar or bubble menu.
- Use TipTap placeholder extension instead of the overlay-only empty hint, or combine both if needed for the title/body split.
- Normalize keyboard shortcuts through TipTap commands so standard shortcuts work consistently.

### Phase 4: Add higher-value insert tools carefully
After the baseline tooling is stable, add richer content blocks in priority order:
1. Tables.
2. Task lists.
3. Slash command menu.

Notes:
- Tables and task lists are the safest next additions because they map well to standard document editors and fit TipTap cleanly.
- Image embeds are explicitly out of scope for this implementation pass and should be deferred entirely.
- Slash commands are a UX layer on top of existing commands, so they should come after the core command set exists.

## Files to change during implementation
- `client/package.json` - add TipTap extension dependencies.
- `client/src/editor/editorConfig.ts` - register and configure new extensions.
- `client/src/editor/Toolbar.tsx` - expand controls and command wiring.
- `client/src/editor/Editor.tsx` - improve bubble menu, link editing UX, and placeholder handling.
- `client/src/editor/extensions/` - add any custom wrappers needed for link behavior or future editor commands.
- optional new files under `client/src/editor/components/` or similar for toolbar dropdowns/popovers if the toolbar becomes too large.

## Guardrails
- Keep TipTap JSON as the canonical content format.
- Keep collaboration support intact by ensuring new extensions work with the current Yjs-backed editor instance.
- Avoid introducing features that require backend support unless that support already exists or is explicitly planned.
- Preserve current save/update flow in `client/src/pages/Editor.tsx` and `client/src/hooks/useDocument.ts`.

## Suggested implementation order
1. Add schema/extensions in `client/src/editor/editorConfig.ts`.
2. Expand `client/src/editor/Toolbar.tsx` for the new commands.
3. Update `client/src/editor/Editor.tsx` bubble menu and link UX.
4. Add tables and task-list insertion controls.
5. Run `npm run lint --workspace client`, `npm run test --workspace client`, and `npm run build --workspace client`.

## Implementation scope for the next execution pass
- Include: underline, strike, highlight, inline code improvements, multiple heading levels, code block, horizontal rule, text alignment, task lists, tables, placeholder, character count integration, richer toolbar controls, richer bubble menu controls, and inline link editing UX.
- Exclude: image embeds, uploads, media management, and any backend changes that would be needed to support those features.

## Expected result
After implementation, the editor should feel closer to a standard modern writing editor: richer formatting, better insertion tools, better contextual controls, and a cleaner path for future additions like slash commands.

## Follow-up options after this plan
- Revisit image embeds in a separate phase once storage/product requirements are defined.
- Add a slash command palette for quick inserts.
- Add comments/suggestions only if collaborative review is a product goal, since that is a larger feature than standard formatting.
